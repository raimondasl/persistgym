## Time, cost and tokens per action (16 recordings)

Per-step values come from each recording line's action metadata. Cost = summed `cost.total_cost` (ARC's no-cache list accounting: input and output tokens x $0.75 / $3.75 per M; includes harness-summary compaction calls). `cost_cached_price_usd` re-prices cached input at $0.075/M (an estimate of billed cost with implicit caching, not ARC's number). Visible output = output_tokens - reasoning_tokens. Seconds per step = gaps between consecutive recording timestamps (server time). Action-call input excludes the compaction call's input on compaction steps. Plateau: warm-up ends at the first model step whose action-call input tokens reach 90% of the run's 95th percentile of action-call input tokens; plateau statistics use the model steps after it. Compaction events = steps carrying `state.harness_compaction` (Adapter only; the Standard harness has no compaction, and its drop-oldest truncation leaves no trace in the recording). Multi-attempt steps (heuristic): action-call input > 1.5 x (previous step's action-call input + its output tokens + min(frames observed, 7) x 13k), previous action-call input >= 30k, neither step a compaction step; i.e. more input than one turn of growth can explain, as when usage sums two or more attempts (agent.py L1018-1030).

## Clean-run cost upper bound (8 games x 2 harnesses)

Cost a run would have had if it had not stopped early, at plateau cost per action.

``bound_stop_level_usd`` (the PLAN §16.4 definition): measured cost of every action taken
+ the stopping level's remaining 5x budget x plateau cost per action. This is what the run
would cost had it kept playing the level it stopped on until its budget ran out.
``bound_full_game_usd`` adds the 5x budgets of all later levels too, the worst case if the
run had also cleared the stopping level. For GAME_WIN and ACTION_BUDGET runs nothing
remains on the stopping level, so the first bound equals the measured cost.
Wall-clock check: (actions taken + remaining stop-level budget) x the run's mean seconds
per action, against the 12 h budget. ``bound_stop_level_12h_usd`` caps the remaining
actions at those that fit in what was left of 12 h at that pace (the harness would have
ended with TIME_BUDGET first).

## What this does not show

- Exit reasons are inferred, not observed; ERROR_OR_CLOSED pools API errors, agent (parse) errors and scorecard closures.
- One published run per game and config: no seed variance; nothing here is a harness effect estimate.
- Costs are ARC's no-cache list accounting from the recordings, not billed cost; per-action numbers come from 8 games chosen for the path study, not all 25.
- Clean-run bounds assume the plateau cost per action holds for the remaining budget; the uncapped bound ignores the 12 h clock and the capped one assumes the run's own mean pace. They are planning numbers, not forecasts of our runs (service tier, latency and model behaviour can differ).
- No per-level clear rates by harness (H5) are computed or implied.
